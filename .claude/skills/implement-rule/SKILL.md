# 규칙·로직 구현

진단이 끝난 수정안을 최소 변경으로 코드에 옮기고, 합성 데이터 테스트로 고정한 뒤 검증 에이전트에 넘긴다.

## 절차

1. **입력을 확인한다.** `docs/issues/<slug>.md`의 "수정안"과 "검증 샘플". 기록이 없으면 CLAUDE.md "작업 라우팅"의 폴백 규칙을 따른다.
2. **최소 변경.** 수정안에 적힌 함수만 고친다. 본문 텍스트 보존 원칙: 치환은 원문 위치를 찾았을 때만, 못 찾으면 그대로 둔다. 파일 입출력은 `encoding="utf-8"`.
3. **테스트를 먼저 깨뜨린다.** `tests/`에 합성 데이터로 실패→통과 케이스를 넣는다. 깨졌던 샘플은 합성 문자열로 축약한다(PDF 커밋 금지). `mathocr`의 정리 규칙을 바꿨으면 `OCRCache.VERSION`을 올린다.
4. **옵션이 생기면** `option-wiring` 에이전트에 이름·타입·기본값·한 줄 설명을 주어 다섯 곳 배선을 맡긴다.
5. **검증은 `verify-run` 에이전트.** pytest, 검증 샘플 회귀, `main_gui.bat`을 건드렸으면 ASCII/CRLF/라벨 검사. 요약만 받고 실패면 2로 돌아간다.
6. **멈춘다.** 커밋하지 않는다. 사용자가 커밋을 시키면 `commit-pr-draft`로 문안을 받아 메인 세션에서 커밋한다.

## 산출물

- 변경 파일 목록, 추가한 테스트 이름, `verify-run` 요약.
- 메인 세션에는 diff 전체를 올리지 않는다.
