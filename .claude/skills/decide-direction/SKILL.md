# 방향 결정

코드를 쓰기 전에 "무엇을 할지"를 정하고, 뒤 단계(진단·구현·검증)가 감이 아니라 기준으로 판단할 수 있게 기록한다.

## 절차

1. **질문을 한 문장으로 고정한다.** "수식 OCR 신뢰도를 높인다"는 질문이 아니다. "엔진을 바꿀지, 검증 지표를 고칠지, 둘 중 먼저 할 것은?"처럼 선택지가 보이게 쓴다.
2. **항상 참인 제약을 먼저 적는다.** Python 3.12 고정(numpy<2) · 기본 설치는 CPU 전용(torch 계열은 extra로만) · Windows 더블클릭 설치(`main_gui.bat`) · 논문 PDF 커밋 금지 · 본문 텍스트 보존 · 이미지→LLM 방식은 수식 수만큼 토큰이 든다.
3. **대안을 2~4개 세우고 같은 축으로 비교한다.** 효과(정확도·속도) / 설치 리스크(Windows, CUDA, wheel) / 비용(토큰·시간·크레딧) / 되돌리기 난이도. 근거가 없으면 조사한다. 자료가 많은 조사는 `Explore` 서브에이전트에 맡기고 결론만 받는다. 작은 벤치마크가 필요하면 사용자 PC에서 돌릴 명령 한 줄을 준다. 이 세션에서 돌릴 수 없는 것은 돌린 척하지 않는다.
4. **사용자에게는 가치 판단만 묻는다.** 비용 대 정확도, 지원 범위, 어디까지 자동화할지. 사실은 묻지 않고 조사한다. 질문은 한 번에 2개 이내.
5. **기록한다.** `docs/decisions/<slug>.md`, 틀은 `docs/decisions/_template.md`. **판정 기준** 절을 반드시 채운다. 예: "텍스트 레이어에 `ð` `þ` `Þ`가 2개 이상이면 깨진 레이어로 보고 신뢰도 비교를 건너뛴다", "엔진 교체는 벤치마크 기준 신뢰도 중앙값이 +0.1 이상 오를 때만", "이미지→LLM 방식은 논문 한 편당 토큰 상한 N 이내일 때만".
6. **되돌릴 조건을 적는다.** 어떤 결과가 나오면 이 결정을 폐기하는지.

## 산출물

- `docs/decisions/<slug>.md` 한 장.
- 메인 세션에는 결정 요약 5줄 이내와 파일 경로만.

## 하지 않는 것

- 코드 수정(그건 `implement-rule`), 커밋.
- 결정 없이 "둘 다 해 보자"로 끝내기. 미룰 때는 상태를 "임시"로 표시하고 되돌릴 조건을 적는다.
