# 수식 LaTeX 신뢰도: 엔진 교체보다 검증 계층과 측정 체계를 먼저

- 날짜: 2026-10-19
- 상태: 결정
- 만든 스킬: decide-direction

## 질문
수식 LaTeX 신뢰도를 높이기 위해 (A) 검증 계층 수정, (B) 하이브리드(rapid → 불확실할 때만 Claude), (C) 로컬 GPU 엔진, (D) 측정 체계 중 무엇을 먼저 하고 무엇을 뺄 것인가.

## 제약
- Python 3.12 고정(`rapid_latex_ocr` → numpy<2). 기본 설치는 CPU 전용, torch 계열은 extra로만.
- Windows 더블클릭 설치(`main_gui.bat`)가 깨지면 안 된다.
- 논문 PDF와 변환 결과는 커밋하지 않는다. 테스트는 합성 데이터만.
- 본문 텍스트는 망가뜨리지 않는다.
- **사용자 결정(2026-10-19): API(Claude 비전) 호출 없이 전부 로컬로 한다. GPU 엔진 재도전은 이번 라운드에서 제외하고 결과를 보고 정한다.**

## 대안과 비교
| 대안 | 효과 | 설치 리스크 | 비용 | 되돌리기 |
|---|---|---|---|---|
| A. 검증 계층 수정 — 깨진 텍스트 레이어 감지, `ð3Þ` 식 번호 정규화, 신뢰도 오경보 제거 | OCR 정확도 자체는 그대로. 2026-10-18 벤치마크(paper-01, 5식)에서 "불확실" 4건 중 4건이 깨진 텍스트 레이어 때문인 오경보였고, 식 (3)의 번호 분리 실패도 같은 원인 | 없음 | 없음 | 쉬움 |
| B. 하이브리드 엔진 `auto` | Claude 정확도를 불확실한 식에만 적용 | 없음 | 토큰이 불확실한 식 수에 비례 | 쉬움 |
| C. 로컬 GPU 엔진(torch 계열 extra) | 수식 단독 벤치마크에서 pix2tex(=rapid) 대비 큰 폭 향상(UniMER-Test CDM 0.64 → 0.97) | Windows CUDA 설치가 실패 지점. PaddlePaddle 시도는 모델 로드 전에 막혔음 | 개발 시간 큼 | 어려움(의존성·문서·bat) |
| D. 측정 체계 — 벤치마크 스크립트 + 정답 LaTeX 골든 셋 | A·C의 효과를 숫자로 판정 | 없음 | 작음 | 쉬움 |

근거: 2026-10-18 벤치마크에서 rapid는 식 (1)을 굵은 글꼴만 빼고 정확히 읽었고 식 (4)도 구조는 맞았다(악센트·위첨자 3곳 오류). "정확도가 낮다"는 인상의 대부분은 엔진이 아니라 **신뢰도 지표가 깨진 텍스트 레이어(`¼`=`=`, `þ`=`+`, `ð Þ`=괄호, `@`=∂)와 대조해 낸 오경보**였다. 구형 Elsevier 등 Type 1 사설 인코딩 PDF에서 공통으로 나타난다.

## 결정과 이유
1. **D를 작게 먼저**: `tools/bench_mathocr.py`(2026-10-18 작성분, 폐기 브랜치에 있던 것을 복원)에 정답 LaTeX 골든 셋 비교 모드를 더한다. 결과와 골든 셋은 PDF마다 `bench/<pdf stem>/` 한 폴더에 둔다(`report.html`, `results.json`, 크롭, `golden.json`). 커밋되는 것은 `golden.json`(쪽, 식 번호, 정답 LaTeX)뿐이고 PDF는 사용자 PC에만 둔다.
2. **A를 바로**: 아래 판정 기준대로 `mathocr.py`·`converter.py`의 검증 계층을 고친다. 엔진은 건드리지 않는다.
3. **B는 뺀다**: 사용자 결정(전부 로컬).
4. **C는 보류**: 되돌릴 조건에 걸릴 때만 재도전. 재도전 시 PaddlePaddle은 제외하고 pip 한 줄로 끝나는 torch 계열(UniMERNet 등)만 후보.

## 판정 기준
- **깨진 텍스트 레이어**: 수식 영역의 텍스트에 `ð` `þ` `Þ`가 합쳐 2개 이상이면 깨진 것으로 본다. 깨진 영역에서는 (a) `hint_fixes` 보정을 건너뛰고, (b) `hint_similarity`는 1.0(판단 유보)을 돌려 `⚠ OCR 신뢰도 낮음`을 붙이지 않으며, (c) 사용자에게는 대신 `텍스트 레이어 없음/손상 · 이미지와 대조` 안내를 붙인다.
- **깨진 레이어 식의 배율 선택과 신뢰도(2026-10-19 보강)**: 텍스트 레이어로 고를 수 없으므로 **배율 간 일치도**를 쓴다. 2배와 3배로 읽어 정규화한 LaTeX(`normalize_latex`)가 **완전히 같으면** 채택하고, 조금이라도 다르면 4배까지 읽어 다른 결과와 가장 많이 일치하는 것을 고른다(동률이면 큰 배율). 신뢰도 = 최고 쌍 일치도(`difflib`). 결과가 하나뿐이면 판단 유보(1.0). 유사도 0.9 같은 느슨한 기준은 쓰지 않는다 — 긴 식에서 기호 세 개가 틀려도 0.9를 넘는 것을 테스트에서 확인했다. 이 신뢰도가 0.6 미만이면 `⚠`를 붙인다 — 깨진 레이어에서도 근거 있는 경고가 생긴다. 이유: 힌트를 비우자 첫 배율에서 멈춰 식 (1)이 `\chi\circ`→`\gamma\propto`로 나빠졌다(2차 검증). 텍스트 레이어가 아예 없는 PDF(이미지·벡터 수식)는 이번에 바꾸지 않는다(후속 후보).
- **식 번호**: `LABEL_RE` 매칭 전에 `ð`→`(`, `Þ`→`)`로 정규화한다. `ð3Þ`도 식 번호로 잡혀 영역이 분리되어야 한다. 2단 조판에서는 오른쪽 정렬 판정을 탐색 띠가 아니라 수식 박스 기준으로 한다(2026-10-19 보강).
- **A의 성공 기준(paper-01.pdf 2쪽, 5식)**: 불확실 표시 4건 → 0건, 식 (3)의 LaTeX 끝에 번호 `(3)`이 섞이지 않음, 식 (1)·(4)의 LaTeX는 수정 전과 동일(회귀 없음).
- **엔진 재도전(C) 조건**: A·D 이후 골든 셋에서 rapid의 정규화 정확 일치율이 60% 미만이거나, 텍스트 레이어가 멀쩡한 PDF에서 신뢰도 중앙값이 0.75 미만이면 C를 다시 연다. 둘 다 넘으면 엔진 교체는 하지 않는다.
- **골든 셋 비교 방식**: LaTeX를 `tools/bench_mathocr.py`의 `normalize_latex`로 정규화해(굵기·괄호 크기·`\mathrm`/`\text` 포장·간격 명령·환경·중괄호·공백·끝 쉼표는 버리고, 악센트·첨자·기호·괄호는 유지) 정확 일치율과 `difflib` 유사도를 함께 낸다. 글자만 남기는 `_latex_letters`는 `\tilde`/`\bar` 차이(식 (4)의 실제 오류)를 못 보므로 채점에는 쓰지 않는다(2026-10-19 테스트에서 확인). 렌더링 기반 지표(CDM)는 쓰지 않는다(의존성 추가 금지).

## 결과 (2026-10-19)
- **골든 셋 4개 확정 후 채점(사용자가 (1)(2)(4)(5) 확정, (3)은 미확정)**: rapid 정확 일치 **0/4**, 평균 유사도 0.745.
  남은 차이는 모두 진짜 OCR 오류다 — (1) 굵은 `\chi` 두 곳이 `\gamma`(0.935), (2) 두 줄짜리 긴 식에서 `CO`가 `Go`로
  네 번, `\tilde u`가 `\bar u`로 등 다수(0.171), (4) `\varphi` 세 곳이 `\phi`(0.957; 첫 실행의 틸드·위첨자 오류는 배율 간
  일치도 선택으로 사라짐), (5) `\tilde p`가 `\tilde r`, `min`의 `i`가 `o`(0.915). 표기 차이(`\widetilde`/`\tilde`,
  `aligned`의 `&`, 중괄호·공백)는 `normalize_latex`가 이미 걸러낸 뒤의 수치다.
  → "정확 일치율 60% 미만이면 C를 다시 연다"는 조건에 **이 논문에서는 걸린다.** 다만 깨진 Type 1 글꼴·굵은 그리스 문자·2단
  조판이 겹친 한 편이므로, 정상 레이어 논문 한 편을 같은 방법으로 재어 본 뒤 C(로컬 GPU 엔진)를 열지 결정한다.
- A의 성공 기준: 불확실 표시 4건 → 0건 ✓, 식 (3) 번호 분리 ✓, 식 (1)·(4) LaTeX 회귀 없음 — **부분** (식 (1)의 마지막 `\chi`가 `\gamma`. 수정 전의 완전 정답은 깨진 유사도로 세 배율 중 하나를 "우연히" 고른 결과였고, 지금은 배율 간 다수결이 한 기호를 놓친다).
- 엔진 재도전 조건은 아직 평가할 수 없다: 골든 셋 확정 항목이 2개뿐(정확 일치 0/2, 유사도 0.946)이고 정상 레이어 논문이 없다. 다음 할 일: `bench/paper-01/golden.json`의 (2)(3)(5)를 `bench/paper-01/report.html`과 대조해 확정하고, 정상 레이어 논문 한 편을 `tools/bench_mathocr.py`로 돌려 추가한(첫 실행이 `bench/<stem>/golden.json` 틀을 만듦) 뒤 조건을 본다.

## 되돌릴 조건
- A를 적용한 뒤 텍스트 레이어가 멀쩡한 논문에서 불확실 표시가 **늘면**(오경보 제거가 아니라 진짜 오류를 숨기는 것이면) 깨진 레이어 판정 임계값(2개)을 올리거나 (b)를 되돌린다.
- 위 "엔진 재도전 조건"에 걸리면 C를 연다. 그 전에는 엔진을 바꾸지 않는다.
