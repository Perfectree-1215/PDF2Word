# MD 그림을 LLM 인제스트용으로: 그림 설명 텍스트를 변환 때 만들 것인가, 그림 파일 수를 줄일 것인가

- 날짜: 2026-10-23
- 상태: 결정 (2026-10-23 사용자 답: 변환 때 API 지출 불가, 그림 설명은 달지 않음 → A 폐기; B1(패널 병합) 구현; 이어서 사용자가 원한 것은
  "논문 그림 전부를 한두 장에 모으기"로 확인되어 B3를 토큰 예산 설계로 재개)
- 만든 스킬: decide-direction

## 질문
LLM-Wiki 인제스트에서 그림 때문에 생기는 토큰 중복(그림 한 장마다 비전 호출 + 설명 출력)을 줄이려면
(A) 변환 때 그림마다 설명 텍스트를 한 번 만들어 MD 안에 넣어 MD 혼자서 완결되게 할지,
(B) 그림 파일 수를 줄일지(B1 패널 병합 · B2 로고 같은 노이즈 제거 · B3 여러 그림을 한 장에 모은 모음 이미지),
(C) 그림을 내장한 단일 파일(base64 MD · PDF 재생성 · Word)로 낼지 — 무엇을 먼저 할 것인가.

## 제약
- 항상 참: Python 3.12 고정, 기본 설치는 CPU 전용(torch 계열 금지), Windows 더블클릭 설치(`main_gui.bat`), 논문 PDF·변환 결과
  커밋 금지, 본문 텍스트 보존, 이미지→LLM 방식은 그림 수만큼 토큰이 든다.
- 사용자 결정 2026-10-19 "API 호출 없이 전부 로컬"은 **수식 OCR**에 대한 것이었다. 그림 설명은 torch 없는 로컬 대안을 이번 조사에서
  찾지 못했으므로(아래 "조사한 사실") API를 쓸지가 이 결정의 가치 판단 1이다.
- Claude 비전 토큰 규칙(2026-10-23 공식 문서 확인): 이미지는 28×28 px 패치당 1 토큰, 즉 `⌈w/28⌉×⌈h/28⌉`. Claude 4.7 이후 모델은 긴 변
  2,576 px·4,784 토큰까지 원본 해상도로 보고 그 이상은 축소(이전 모델은 1,568 px·1,568 토큰). **토큰은 면적에 비례**하므로 파일을
  합쳐도 입력 토큰은 거의 줄지 않는다. 줄일 수 있는 것은 호출(턴) 수와 출력 토큰, 또는 이미지를 아예 보내지 않는 것뿐이다.
- 에이전트식 인제스트(Claude Code·Cowork의 Read 도구는 PNG를 이미지로 모델에 넘긴다)는 **그림 한 장 = 턴 하나**: 그때까지의 컨텍스트를
  다시 보내고(캐시 읽기 과금) 설명을 새로 출력하며, 그 결과가 이후 모든 턴의 컨텍스트에 남는다. 그림 한 장의 실제 비용은 이미지
  토큰(~1.5K)이 아니라 "턴 하나 + 컨텍스트 증가"다. 같은 논문을 다시 인제스트하거나 다른 대화에서 열면 다시 든다.
- claude.ai 채팅 업로드는 메시지당 이미지 20장 한도. paper-01은 md 1 + png 19 = 딱 20장이다.
- Word(.docx) 속 이미지는 Claude가 보지 못한다(사용자 관찰). Word 경로로는 그림 정보가 전달되지 않는다.

## 조사한 사실 (2026-10-23, 이 PC)

## 결정과 이유
**사용자 결정(2026-10-23)**: 변환 때 Claude API 토큰을 쓰지 않고(전부 로컬), 그림 설명 텍스트도 달지 않는다. 따라서 **A는 폐기**. 같은 날 사용자가
**B1(같은 캡션의 패널을 한 장으로 병합)을 진행**하기로 골랐다 — 분할 샘플 PDF가 이 PC에 없으므로 합성 테스트로 규칙을 검증하고, 실제 PDF 회귀는
사용자가 분할이 생기는 논문을 주면 돌린다. B2(1쪽 로고·표지 제거)와 D(README 인제스트 규칙)는 제안으로 남긴다(원하면 추가). C는 하지 않는다.
로컬 VLM 조사는 사용자가 그림 설명을 원하게 될 때 별도 결정으로 연다.

**재선택(2026-10-23, B1 구현 뒤)**: 사용자가 "한 장으로 병합"으로 떠올린 것은 B1이 아니라 **B3 — 논문의 그림 전부를 한 장(또는 몇 장)에 모아
파일 수를 크게 줄이는 것**이었다. B3를 기각한 이유(여러 그림을 한 장에 넣으면 축소돼 글자·눈금이 안 읽힘)는 시트 한 장을 Claude가 원본 해상도로
읽는 한도 안에 맞추면 사라진다: Claude 4.7 이후 모델은 긴 변 2,576 px·28 px 패치 4,784개까지 축소하지 않는다(위 제약). 그래서 B3를
**토큰 예산 패킹**으로 재개한다 — 타일을 150 dpi로 그려 한 장이 한도를 넘으면 다음 장으로 넘기므로 업로드 때 축소가 0이고, 읽기 해상도는
`--sheet-dpi`로 조절한다. paper-01(이미지 19장, 12.6K 토큰)은 3~4장이 된다. B1은 그대로 둔다(병합된 패널이 타일 하나가 됨).

제안 당시의 근거(A 권고, 기록용):
- 측정상 토큰의 절반이 그림이고, 그 비용의 본질은 이미지 크기가 아니라 "그림 한 장 = 턴 하나 + 매번 반복"이다. 파일을 합치는 B 계열은
  턴 수만 줄이고(B1은 이 논문에선 효과 0), 이미지를 보내지 않는 A만 토큰·턴·반복을 모두 없앤다.
- A는 비용을 "인제스트마다 비싼 모델의 긴 컨텍스트 안에서"가 아니라 "변환 때 한 번, 짧은 컨텍스트, 고를 수 있는 모델"로 옮긴다. 같은 Opus끼리도
  1.5배, Sonnet 3배, Haiku 60배 싸고, 인제스트 횟수만큼 배수가 커진다.
- 기본값은 `none`(현행 유지)이다. 이 프로젝트의 원칙(로컬·무료 기본)과 2026-10-19 결정을 지키고, 위키용 변환에서만 사용자가 켠다.
- 가치 판단 1(API 지출 허용?)·2(기본 모델)는 위 사용자 결정으로 닫혔다: 허용 안 함, 설명 없음.

## 구현 설계 (implement-rule · option-wiring 인계)
사용자 결정으로 1·2(그림 설명)는 폐기, 3(B2)은 보류. 진행하는 것은 4(B1)와 5의 B1 테스트이며 실제 인계물은 `docs/issues/figure-panel-merge.md`.
1. **새 모듈 `pdf2word/figdesc.py`** — 본문 MD가 다 조립된 뒤의 후처리 패스(`Converter._run`에서 `finalize_subfigures` 다음, `postprocess` 전).
   - 대상 임베드: `fig*.png`·`table*.png`(캡션 기준 이름)과 `p<쪽>-img*.png`. 제외: `eq-*.png`, `inline*`(수식·기호).
   - 입력 묶기(이미지를 먼저 두는 것이 공식 권고): [이미지] → 캡션 줄(임베드 앞뒤에서 `looks_like_caption`인 줄) → 본문에서 그 번호를 언급하는
     문장("Fig. 5", "Figure 5", "Figs. 5 and 6", 최대 1,200자) → 지시문.
   - 지시문 요지: 그림 유형 / 무엇을 그렸나(축·단위·범위·계열·조건) / 핵심 수치(읽히는 값만, ≈로 표시, 안 읽히면 "not legible") /
     요지 1–2문장 / 이미지 속 글자(범례·주석). 표를 찍은 그림이면 설명 대신 Markdown 표로 옮긴다. 캡션 내용을 반복하지 않는다. 200단어 이내,
     캡션과 같은 언어. 출력은 평문 줄(중첩 목록 없음).
   - 출력 형식: 캡션 줄 뒤(캡션이 없으면 임베드 바로 뒤)에 접힌 콜아웃
     `> [!figure]- 그림 설명 (자동 · claude-sonnet-5-5)` + `> ` 줄들. Obsidian에서는 접혀 보이고 LLM은 텍스트로 읽는다.
   - 캐시: `OCRCache` 재사용. key = `figdesc:<model>:v1:<캡션 sha1>` + PNG 바이트 → 같은 그림·캡션은 재변환 때 무료. 실패 호출은 캐시하지 않음(수식과 동일).
   - API 배관: `mathocr.ClaudeEngine._create`(서버측 폴백 베타·effort·구형 SDK 대비)를 공용 함수로 빼서 공유. `max_tokens` 1024, 재시도 3회,
     호출당 60 s, 이미지는 긴 변 2,000 px 넘으면 Pillow로 축소해 전송(파일은 그대로). `stop_reason == "refusal"`·오류·`max_tokens` 초과는 그 그림만

## B3 구현 설계 (2026-10-23, implement-rule 인계)
1. **새 모듈 `pdf2word/sheets.py`**: `apply_sheets(body, asset_dir, style, dpi, fallback_dpi, mode)` — 변환이 끝난 MD 본문에서 **한 줄 전체가
   임베드인 줄**(`![[폴더/파일]]`·`![alt](폴더/파일)`)을 순서대로 모은다. 대상은 자산 폴더에 실제로 있는 `fig*`·`table*`·`p<n>-img*`·`eq-*`;
   `inline*`(문장 속 기호 이미지)과 없는 파일은 건드리지 않는다.
   - 타일: 저장된 PNG를 그 파일의 dpi(`Pixmap.xres`, 없으면 `--dpi`)에서 `--sheet-dpi`(기본 150)로 줄인 크기. 라벨 띠(26 px, "Fig. 3"·"Fig. 3a"·
     "Table 2"·"Eq. (2)"·"p4-img10") + 1 px 테두리, 간격 16 px.
   - 시트: 선반(행) 채우기, 문서 순서 유지. 한 장은 **1,932 px × 1,932 px 이내**(28 px 패치 69×69 = 4,761 ≤ 4,784, 긴 변 ≤ 2,576) —
     Claude 4.7 이후 모델이 축소 없이 읽는 한도. 넘치면 다음 장(`sheet-1.png`, `sheet-2.png` …). 타일 하나가 시트보다 크면 그 타일만 맞춰 줄인다.
     시트 폭·높이는 쓴 만큼만(남는 여백은 잘라 토큰 절약).
   - 그리기: PyMuPDF 새 페이지(1 pt = 1 px)에 `insert_text`(Helvetica)·`insert_image`·`draw_rect` 후 `get_pixmap(Identity)` → PNG. 글꼴 파일·Pillow 불필요.
   - 본문: `replace`면 임베드 줄을 `*[Fig. 3 → sheet-1.png]*`로 바꾸고(캡션·본문은 그대로), 끝에 `## 그림 모음 (figure sheets)` 절을 붙여
     `sheet-1.png: Fig. 1 · Eq. (1) · Fig. 2` 한 줄 + 시트 임베드를 적는다. `add`면 임베드는 그대로 두고 절만 붙인다.
   - 반환: 새 본문, 시트 파일 목록, 타일로 들어간 파일 목록(`replace`에서 지울 것).
2. **`converter._run` 훅**: `postprocess`·`ensure_title` 뒤, 프론트매터 전에 `fmt in (md, both)`이고 `figure_sheet != "none"`이면 적용.
   MD는 시트 본문으로, **docx는 원래 본문으로** 만들고(그림이 아직 있음), docx까지 쓴 뒤에 `replace`의 개별 PNG를 지운다. 실패하면 경고 한 줄 뒤
   현행 출력. `stats["figure_sheets"]` → 프론트매터 `figure_sheets: N`, 끝 로그에 `figure sheets N`. `GENERATED_RE`에 `sheet`를 넣어 재변환 때 옛 시트를 지운다.
3. **옵션(option-wiring)**: `figure_sheet: "none" | "add" | "replace"`(기본 none), `sheet_dpi: 150`. CLI `--figure-sheet`, `--sheet-dpi`; GUI 콤보
   "그림 파일: 개별 파일(기본) / 개별 + 모음 시트 / 모음 시트만"; README 옵션 표·"LLM 위키용" 권장(`-f md --figure-sheet replace`); CHANGELOG `## 미공개`.
4. **테스트 `tests/test_sheets.py`**(합성 PNG, 모델 없음): 라벨 변환, 패킹이 한도를 지키고 순서를 유지, replace/add 본문 재작성, 마크다운 링크
   스타일, inline·없는 파일 제외, 변환 전체(`_run` 가짜 레이아웃)에서 `replace`가 개별 PNG를 지우고 docx는 그대로 만들어지는지.

  나오면 기본값을 `split`으로 바꾸고 조건(텍스트 10%·120자, 면적 3배)을 다시 잰다.
